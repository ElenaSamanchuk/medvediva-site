# Архитектура миграции

Цель: собственная реализация на Vue + Tailwind без Tilda JS, CSS, CDN, форм и зависимых модов. Шрифты/медиа хранить локально с checksum. Бизнес-сервисы NN99, ЛК, боты, магазины и согласованную аналитику сохранять после проверки назначения.

## Уже реализовано

Изолированный Vue/Vite/Tailwind workbench и компонент SupportForm. Четыре поля соответствуют публичной форме form627240945: ник Telegram, вопрос (required), email (required), телефон. Собственная валидация, доступные подписи/ошибки, защита от одновременной отправки, состояния ошибки и неподтверждённой доставки. Транспорт не зависит от Tilda; default unconfigured. Режим dry-run не вызывает fetch и ничего не сохраняет. Формулировки/шрифты/полный вид popup ещё не приняты, часть пояснений сокращена в локальном preview.

## Контракт формы — черновик

Live endpoint пока отсутствует. Клиент посылает только telegram/message/email/phone; сервер должен валидировать поля, лимитировать запросы, безопасно доставлять получателю, сохранять необходимые согласия и исключать дубли. Необходимо определить retention, idempotency key и семантику ответа. Текущий клиент сообщает успех только при delivery=delivered и непустом id; accepted/200 оставляет unconfirmed. Этот контракт должен быть согласован с реальным сервером; тесты клиента не доказывают доставку.

Аналитика и chat widget подключаются отдельно от источников Tilda, с сохранением согласий и событий. Никакие секреты или защищённые сессии не включать в frontend.
