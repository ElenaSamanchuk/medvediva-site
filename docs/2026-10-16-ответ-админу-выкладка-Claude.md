Общие правила VM:

- Скрипты выкладки меняют только папку своего сайта. Конфиги nginx, `sites-enabled`, `conf.d`, сертификаты — вручную: `sudo nginx -t && sudo systemctl reload nginx`, не `restart`.
- nginx 1.24, Node и Docker нет — собираем локально.
- На VM ничего не фильтрует. Из обычной сети Елены она не открывается, поэтому **Елена выкладывает вручную через VPN**.
- Ресурсы: 2 ГБ RAM, свободно 55 ГБ; релиз medvediva ~320 МБ, держим 2–3 последних.

### `server-check-shared.sh` — когда STOP

- в `sites-enabled` что-то кроме `kochfit` и `medvediva`, включая `default`;
- конфиг `medvediva` не включён, или в нём не `server_name preview.medvediva.ru`, или не `root /var/www/medvediva/current`;
- у medvediva есть `default_server` или `server_name _`;
- `preview.medvediva.ru` объявлен ещё в каком-то конфиге;
- в `conf.d` есть `.conf` — он действует и на kochfit;
- нет сертификата `/etc/letsencrypt/live/preview.medvediva.ru/`.

Если релизов больше трёх — WARN.

### `server-activate-shared.sh` — порядок

1. `nginx -t` и статус kochfit.ru — «до».
2. `chmod -R a+rX` релиза → `ln -sfn releases/$REL current`.
3. Проверка через `curl --resolve preview.medvediva.ru:443:127.0.0.1`:
   - главная — 200;
   - несуществующий путь — 404;
   - есть `X-Robots-Tag: noindex`.
4. Не прошло → `current` возвращается на прошлый релиз.
5. Сравнение «до/после»: kochfit.ru, конфиги, `sites-enabled`. Разница — WARN.

### Остаётся вручную
